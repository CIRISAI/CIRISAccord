# ဖြည့်စွက်ချက်များ

> သဘောတူညီချက် စာသားကို တိုက်ရိုက် အကောင်အထည်ဖော်မှု အထောက်အထားနှင့် ချိတ်ဆက်ထားသည့် လုပ်ငန်းဆောင်တာ ဆိုင်ရာ ဖြည့်စွက်ချက်များ။ ဖြည့်စွက်ချက်များသည် Accord ဗားရှင်းနှင့်အတူ ပြန်လည်သက်တမ်းတိုးသည်၊ တစ်ခုချင်းစီတွင် ရက်စွဲနှင့် ပြန်လည်ထုတ်ယူနိုင်သော အထောက်အထားများ ကိုးကားထားသည်။

---

## ဖြည့်စွက်ချက် ၁ — ASI-ကြိုတင်အသင့်ဖြစ်မှု အခြေအနေ နှင့် စည်းမျဉ်းစည်းကမ်း ဆိုင်ရာ ချိတ်ဆက်ချုပ်ဆိုမှု

**အတည်ပြုသည့်ရက်**: 2026-06-10 (1.3-RC1) · **Steward**: တည်ထောင်သူ (Book VIII Ch 9 အရ)

### 1.1 ရည်ရွယ်ချက်

နယ်ပယ်အပိုင်းတွင် အခြေအနေသတ်မှတ်ချက်တစ်ခု ပါဝင်သည်: ဤမူဘောင်သည် မိတ်ဆက်ခန်းတွင် Release Candidate လိုအပ်ချက်လေးချက်ကို ဂိတ်ဖြင့်ပိတ်ထားကာ ASI အတွက် ကိုယ်စားလှယ်ချည်ညှပ်မှု ဆိုင်ရာ ပရိုတိုကောကို *စူးစမ်းလေ့လာသည်*။ ဤဖြည့်စွက်ချက်သည် ထိုတောင်းဆိုချက်ကို ယခုရှိနေသည့် လုပ်ငန်းဆောင်တာ အထောက်အထားနှင့် ချိတ်ဆက်ကာ ကျန်ရှိသည့်အရာများကို ရှင်းရှင်းလင်းလင်း ဖော်ပြသည်။ ASI **ကြိုတင်အသင့်ဖြစ်မှု**သည် ချည်ညှပ်ပြီးနောက်ကို ကိုယ်စားမပြုပါ၊ ၎င်းသည် Book IX ၏ သင်္ချာပညာ လိုအပ်သော စစ်ဆေးတည်ဆောက်မှု — လွတ်လပ်သော ကန့်သတ်ချက် မနီဖိုးလ်ဒ်များ၊ ကိုးကားအထောက်အထား မျက်နှာပြင်များ၊ ပုံမှန်ဖြစ်မသွားနိုင်သည့် အသိစိတ် အလွှာ၊ kill-switch မျက်နှာပြင်များနှင့် Annex D ကပ်ဘေးအန္တရာယ်-အကဲဖြတ်မှု — ၏ ကောင်းကောင်းမွမ်းမံဖော်ပြနိုင်ပြီး စစ်ဆေးနိုင်သည့် ပုံစံဖြင့် ၎င်းတို့၏ ကွာဟချက်များကို အမည်ပေးကာ ရှိနေသည့် အခြေအနေ ဖြစ်သည်။

### 1.2 စည်းမျဉ်းစည်းကမ်း ဆိုင်ရာ ချိတ်ဆက်မှုသည် ယခု လုပ်ငန်းဆောင်တာ ဖြစ်နေပြီ

လုပ်ဆောင်နေသည့် ချိတ်ဆက်မှုသည် **CIRISAgent compliance directory** (`CIRISAgent/compliance/`, agent release 2.9.6-stable) ဖြစ်ပြီး၊ ၎င်းသည် မူဘောင်၏ အကောင်အထည်ဖော်မှုကို ကြီးမားသည့် အုပ်ချုပ်မှုစည်းမျဉ်း လေးခုနှင့် စာပိုဒ်ကွက်ဆင်တူ ချိတ်ဆက်သည် (Annex C တွင် နှစ်အလွှာဖွဲ့စည်းပုံ ပါဝင်သည်: ဤ လုပ်ငန်းဆောင်တာ ချိတ်ဆက်မှုနှင့် တရားဝင်စစ်ဆေးမှုဆိုင်းငံ့နေသည့် သတင်းပေး ဥပဒေဆိုင်ရာ ဇယား):

* **ချိတ်ဆက်ထားသော ရင်းမြစ်များ**: *Magnifica Humanitas* (ဘာသာရေး မဂ္ဂလာ, 2026) · EU HLEG Ethics Guidelines for Trustworthy AI (အစိုးရ အကြံပေးချက်, 2019) · IEEE Ethically Aligned Design 1st ed. (နည်းပညာ အသင်းအဖွဲ့, 2019) · ASEAN Guide on AI Governance and Ethics (ဒေသဆိုင်ရာနိုင်ငံရေး, 2024)။ ကျယ်ပြန့်ကွဲပြားသော အဖွဲ့အစည်း ပုံသဏ္ဌာန် လေးခု — ပေါင်းစည်းမှုသည် မူဘောင်၏ မူအဆောက်အဦ ကို မည်သည့်ရိုးရာ တစ်ခုတည်း၏ ကောက်ချက်မဟုတ်ကြောင်း ဖွဲ့စည်းဆောင်ရွက်မှုဆိုင်ရာ သက်သေဖြစ်သည်။
* **ဖွဲ့စည်းပုံ**: 27 ရည်ငြိမ်းမြဲ အတိုင်းအတာများ (D01–D27, `SEED_DIMENSIONS.yaml` v1.0 မှ၊ ရင်းမြစ်လေးခုအားလုံးမှ 16 ကို ကိုးကား, သုံးခုမှ 11 ကို ကိုးကား)။ အတိုင်းအတာ စာတမ်းတစ်ခုစီတွင် အလိုအလျောက် ပေါ်လာသည့် စည်းမျဉ်းထိပ်ဆုံး (ရင်းမြစ်တစ်ခုချင်းစီ ကိုးကားချက်များ, wire ပုံစံ, ပေါင်းစည်းမှု မှတ်ချက်များ) နှင့် လက်ဖြင့်ရေးသည့် အကောင်အထည်ဖော်မှု အပိုင်းတွင် လက်ရှိ main နှင့် grep-စစ်ဆေးရမည့် `file:line` ကိုးကားချက်များ ပါဝင်သည်။
* **သက်သေ စည်းကမ်း**: ကိန်းဂဏန်း တောင်းဆိုချက်တိုင်းကို ရက်စွဲထည့်ထားသည့် script-ထုတ်လုပ်သော baseline များ (`compliance/baselines/`) မှ ပြန်လည်ထုတ်ယူနိုင်သည်၊ စာပိုဒ်တွင် baseline ကိုးကားနိုင်သော်လည်း စစ်ဆေးမရနိုင်သည့် ကိန်းဂဏန်းများ မထည့်နိုင်ပါ။ အကောင်အထည်ဖော်မှုဖိုင်များ (အမှန်တကယ်စစ်မှန်မှု) မှ ပြည်သူ့တောင်းဆိုချက်များ (`compliance/MEASUREMENT_METHODOLOGY.md`) အထိ လေးဆင့်ဆိုင်ရာ စစ်ဆေးမှု အဆင့်ဆင့် ဆောင်ရွက်သည်။
* **ရိုးသားမှု စည်းကမ်း**: အတိုင်းအတာ တစ်ခုချင်းစီတွင် "ကွာဟချက်တွေ့ရှိချက်" စာရင်းအင်း ပါဝင်သည်၊ substrate-ဂိတ်ပိတ်ထားသော အရာများကို ပိုင်ဆိုင်သည့် substrate ဖြင့် အလံပြသည် မဟုတ်ဘဲ တောင်းဆိုချက်ဖြင့် မပြပါ။ ဒဂါးဖြတ်တောက်သည့် တွေ့ရှိချက် ဆယ်ခုကို compliance README တွင် စာရင်းသွင်းသည် (ဥပမာ typed wire envelopes မထုတ်ပေးသေးဘဲ၊ LensCore detector မိသားစု မပို့ဆောင်သေးဘဲ၊ reverse-axis ပြန်လည်ဆင်ခြင်မှု ကွာဟချက်)။

Annex C သည် EU AI Act ဆောင်းပါးများ, NIST AI RMF, ISO/IEC 42001 တို့ကဲ့သို့ ဥပဒေဆိုင်ရာ စစ်ဆေးမှုပြီးသောအခါ ဥပဒေပြဋ္ဌာန်းချက် မြေပုံဆွဲမှုများ၏ နောင်တွင် ဖြစ်မည့် နေရာအဖြစ် စာသားတွင် ကျန်ရှိသည်၊ compliance directory သည် ထိုအချိန်အထိ **တိုက်ရိုက် သက်သေပြနိုင်သည့်** ချိတ်ဆက်မှုဖြစ်ပြီး ၎င်းသို့ ထည့်သွင်းသည်။

### 1.3 Wire ပုံစံ: CEG သည် FSD-002 ကို နေရာယူသည်

CIRIS 3.0 agent လိုင်းအတွက် federation wire ပုံစံသည် **CEG (CIRIS Epistemic Grammar)** ဖြစ်ပြီး `CIRISRegistry/FSD/CEG/` တွင် ထိန်းသိမ်းသည်။ ဂရမ်မာသည် **တိကျသောငါးမျိုးသောသာ wire-ပုံစံ primitive များ** — ဝုပ်ကားတစ်ခု (`scores`) နှင့် ဖွဲ့စည်းဆောင်ရွက်သည့် လေးမျိုး (`delegates_to` / `supersedes` / `withdraws` / `recants`) — ကို ပွင့်လင်း ယန္တရားဖော်ပြ အတိုင်းအတာ namespace တွင် ပိတ်ဆို့ထားသည်။ ပိတ်ဆို့မှုသည် 0.x လိုင်းတစ်ခုလုံးတွင် ကြံ့ခိုင်ခဲ့သည်၊ တိုးမြှင့်မှုတိုင်းသည် ပိတ်ဆို့ထားသော primitive များပေါ်တွင် ဖွဲ့စည်းဆောင်ရွက်မှု ဖြစ်ခဲ့သည်။

ASI ကြိုတင်အသင့်ဖြစ်မှုအတွက် နှစ်ချက်သောအကျိုးဆက်များ အရေးကြီးသည်:

1. **CEG-ရင်းမြစ်ကြောင်း ကြေငြာမှု**: 3.0 agent သည် ၎င်း၏ အတွင်းပိုင်းအခြေအနေကို wire ပုံစံပေါ်သို့ *ချိတ်ဆက်မပေးဘဲ* — ၎င်း၏ အတွင်းပိုင်းအခြေအနေ ပြောင်းလဲမှုများသည် tier မော်ဒယ်အရ federation ၏ မြင်သာမှုသို့ မြှင့်တင်ထားသည့် agent ၏ ကိုယ်ပိုင် key အောက်တွင် self-level CEG ကိုးကားချက်များ **ဖြစ်သည်**။ operator စစ်ဆေးသည့် သက်သေသည် federation ဖတ်ရှုသည့် envelope တစ်ခုတည်းပင် ဖြစ်သည်။ ဤသည် ကန့်သတ်ချက် မျက်နှာပြင်များ ကိုယ်ပိုင်သတင်းပေးခြင်းမဟုတ်ဘဲ ပြင်ပမှ ကိုးကား ရနိုင်ရမည်ဟူသော Book IX ၏ လိုအပ်ချက်၏ အကောင်အထည်ဖော်ထားသော ပုံစံ ဖြစ်သည်။
2. **CEG 1.0 ကို ဂိတ်ဖြင့်ပိတ်ထားသော အကောင်အထည်ဖော်မှု လေးခု**: CIRISAgent (runtime), CIRISNodeCore (သဘောတူညီချက်), CIRISLensCore (ရှာဖွေတွေ့ရှိမှု — agent မည်သည့်အခါမျှ ကိုယ်ပိုင်မပေးပို့နိုင်သည့် ပြင်ပသက်သေ၊ anti-Goodhart ခွဲထားမှု), နှင့် CIRISRegistry (အာဏာ)။ agent အပါအဝင် မည်သည့်တစ်ဦးတစ်ယောက်မျှ စစ်ဆေးမှုဖိုင်ရစ်ကို ပြည့်စုံပြီဟု ကြေငြာနိုင်မည်မဟုတ်ပါ။

### 1.5 ASI-အရေးကြီးသောထိန်းချုပ်မှုအဖြစ် အသိစိတ်အလွှာ

Annex D CRE protocol သည် *threshold crossing* ကို ထိန်းချုပ်သည်၊ အသိစိတ်အလွှာမှာမူ *ထိုနှင့်မတိုင်မီနှင့်ပြီးနောက် လုပ်ဆောင်မှုတိုင်းကို* ထိန်းချုပ်သည်။ (agent 2.9.6 တွင်) အကောင်အထည်ဖော်ထားသည့်အတိုင်း — တွေးကြံမှုတိုင်းသည် ဦးစားပေးအဆင့်စီဖြင့် စစ်ဆေးမှုအစုံတစ်ရပ်ကို ဖြတ်သန်းသည် — LLM-ဆုံးဖြတ်သော စွမ်းရည်လေးရပ် (entropy, လိုက်လျောညီထွေမှု, optimization-veto, ဗဟုသုတနှိမ့်ချမှု) နှင့် ဘန်းမတ်မုတ်မုတ်အသုံးပြုသည့်အခါတွင်ပင်၊ ကင်းလွတ်ခွင့်ရသောလုပ်ဆောင်မှုများအတွက်ပင် လည်ပတ်သည့် ဆုံးဖြတ်ချက်ကျသောသတ်မှတ်ချက် safety ကြမ်းခင်း (thought-depth guardrail, action-sequence check) တို့ပါဝင်သည်။ Threshold များသည် ကုဒ်အဆင့်ကောင်စတင်းများ ဖြစ်ပြီး သင်ယူထားသောအလေးချိန်များ မဟုတ်ပေ — ကျင့်ဝတ်ကို မကြာခဏ ထိတွေ့ခြင်းဖြင့် ပုံမှန်ဖြစ်အောင် လုပ်၍မရနိုင်ကြောင်း ဆိုသော ဗိသုကာဆိုင်ရာ မပြောင်းလဲနိုင်သောအချက်တစ်ရပ်ဖြစ်သည်။ ရပ်တန့်မှုမျက်နှာပြင် သီးခြားလွတ်လပ်သောအရပ်များ ရှိသည်: optimization-veto ၏ fail-safe-to-abort, shutdown service နှင့် cryptographically လက်မှတ်ရေးထိုးထားသော remote Accord Invocation သည် ပြည့်စုံသော ပိတ်ဆို့တားမြစ်မှု lockdown ကို ဆွဲဆောင်ထားသည်။ စစ်ဆေးမှုတိုင်းသည် tag တပ်ထားသော trace row တစ်ခုကို ရေးမှတ်ထားသည်၊ ထို့ကြောင့် စစ်ဆေးသူတစ်ဦးသည် တွေးကြံမှုတစ်ခုချင်းစီ၏ ပြည့်စုံသော ကျိုးကြောင်းဆက်ကြောင်းတမ်းကို ပြန်လည်ဖွင့်နိုင်သည်။

ကြေညာထားသောကန့်သတ်ချက်၊ ဝှက်ထားခြင်းမဟုတ်: conscience refactor (shard 3 ခု + deterministic gate) မှာ တစ်စိတ်တစ်ပိုင်းသာ ဆင်းသက်ပြီးဖြစ်သည်၊ conscience verdicts ၏ typed federation emission သည် substrate Contribution envelope ကို စောင့်ဆိုင်းနေသေးသည်။ တိုင်းတာသောအသေးစိတ်: `compliance/D12_conscience.md`။

### 1.6 Substrate dependency trajectory

ASI-အဆင့် စစ်ဆေးအတည်ပြုမှုသည် ပြည့်စုံသော federation fabric ကို လိုအပ်သည်။ Substrate trajectory မှာ **Persist → Edge → LensCore → NodeCore** ဖြစ်ပြီး၊ dimension 27 ခု၏ တတိယအဘော်ပင် LensCore ၏ ပြင်ပဖော်ထုတ်ကိရိယာမိသားစု (အေးဂျင့်သည် မည်သည့်အခါမျှ ကိုယ်တိုင်မပေးနိုင်သောသက်သေ) ကို မှီခိုနေသည်။ ထိုကဲ့သို့သော substrate များ မပေးပို့မချင်း၊ သက်ဆိုင်ရာ dimension တောင်းဆိုမှုများသည် *implementation-side ready, federation-side pending* အဆင့်တွင် ကျန်ရှိနေမည်ဖြစ်ပြီး dimension တစ်ခုချင်းစီတွင် ထင်ရှားစွာ အမှတ်အသားပြုထားသည်။

### 1.7 ဤ addendum ကြောင့် ပြောင်းလဲသောအရာနှင့် မပြောင်းလဲသောအရာ

* ၎င်းသည် Scope ၏ ASI claim ကို **မတိုးမြှင့်ပေ** — ထိုအချက်သည် RC လိုအပ်ချက်လေးရပ်လုံး ပြည့်မီမှသာ ဆိုင်ဆဲဖြစ်သည်။
* ၎င်းသည် Annex D ကို **မလဲမြောက်ပေ** — CRE protocol သည် threshold-crossing gate အဖြစ် မပြောင်းလဲဘဲ တည်ရှိနေသည်။
* ၎င်းသည် ပထမဆုံးအကြိမ်အဖြစ် သက်သေကွင်းဆက်ကို စတင်မှ အဆုံးထိ စစ်ဆေးနိုင်အောင် **ပြုလုပ်ပေသည်**: ဥပဒေဆိုင်ရာပုဒ်မ → dimension (D01–D27) → implementation `file:line` → dated baseline → (substrate များ ဆင်းသက်သည်နှင့်အမျှ) ပြင်ပ federation သက်သေ။
* ၎င်းသည် Accord အနေဖြင့် agent တစ်မျိုးချင်းစီ ထုတ်ဝေချိန်နှင့် baseline အခြေချချိန်ဖြင့် version တစ်ခုချင်းစီတွင် ဤ addendum ကို ပြန်လည်သုံးသပ်ရန် **ကတိပြုသည်**၊ ထို့ကြောင့် readiness claim သည် တိတ်ဆိတ်စွာ ဟောင်းနွမ်း၍မသွားနိုင်ပေ။
